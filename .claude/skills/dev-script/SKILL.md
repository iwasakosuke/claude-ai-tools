# 開発SOP(スクリプト・自動化ツール)

## 目的
「動くけど再利用できない・壊れても直せない」使い捨てコードをなくす。作ったものを業務資産にする。

## 手順

### 1. 要件を3行で固定する(ここで認識合わせ)
```
入力: 何を受け取るか
出力: 何ができるか
頻度: いつ・誰が実行するか
```
これを提示して承認を得てから書く。**要件の齟齬が最大の手戻り。**

### 2. 実装
- 置き場所: このリポジトリの `tools/<ツール名>/`
- 小さく作る: まず正常系のみ→動作確認→エッジケース対応の順
- 認証情報はコードに書かない。環境変数で受け取り、必要な変数名をREADMEに書く

### 3. テスト・動作確認
- 実データのコピー or ダミーデータで実行して結果を見せる
- 破壊的操作(削除・上書き・送信)を含むツールは必ず `--dry-run` を先に実装し、dry-run結果を確認してから本実行

### 4. ドキュメント(これがないと資産にならない)
`tools/<ツール名>/README.md` に最低限:
- 1行説明 / 使い方(コピペで動くコマンド) / 入力と出力 / 必要な環境変数 / 注意事項

### 5. QA
`checklists/qa-コード.md` を通し、結果を添えて納品する。

## 安全ルール
- main へ直接pushしない。ブランチ→PR
- ファイル削除・上書き・外部送信を行うコードは、その旨を目立つ形で報告し承認を得る
- 課金APIを使う場合は概算コストを先に提示する
