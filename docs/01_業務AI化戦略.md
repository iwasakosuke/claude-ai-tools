## 1. 業務分析(ヒアリング結果+仮説)

### 確認できた事実(本人回答)

| 項目 | 内容 |
|---|---|
| 主な業務 | 資料・コンテンツ制作、開発・エンジニアリング |
| 時間泥棒 | メール・連絡処理 / 資料・ドキュメント作成 / 情報収集・リサーチ・要約 / データ整理・定型レポート |
| 主な成果物 | 提案書・プレゼン資料 / 報告書・議事録・メール文面 / デザイン・画像・SNS投稿 / コード・自動化スクリプト |
| 理想の状態 | 作業時間を半分以下に / 品質を毎回一定に / 判断の迷いをなくす / 業務資産として蓄積 |
| 利用ツール(接続確認済み) | Gmail / Notion / Google Drive / Canva / Figma / GitHub |

### 仮説(未回答部分。違っていたら修正してください)

- **【仮説】** 業務は「制作系(提案書・デザイン・SNS)」と「開発系(スクリプト・ツール)」の2本柱で、メール・レポートはその周辺業務。
- **【仮説】** 過去に自動化を諦めた原因は「作るのに時間がかかる」「作っても保守できない」「品質が信用できず結局手で直す」のいずれか。→ 対策として本資産は「小さく作る・テンプレ化する・QAゲートを必ず通す」設計にした。
- **【仮説】** 触ってはいけない領域は「メールの送信」「SNS・外部への公開」「顧客向け共有ファイルの上書き」「課金が発生する操作」。→ 運用ルール(docs/02)で全Skill共通の禁止事項として明文化した。
- **【仮説】** 成果物の最終保存先は Google Drive または Notion、コードは GitHub。命名・保存ルールは docs/02 に定義した。

## 2. 自動化マップ(業務 × AI化レベル)

AI化レベルの定義:
- **L3 全自動**: AIが完成させ、人は結果を見るだけ
- **L2 AIドラフト**: AIが8割作り、人が確認・修正して確定(★本資産の主戦場)
- **L1 AI補助**: 人が主導し、AIは調査・壁打ち・チェックに使う
- **L0 人間専任**: 判断・関係構築・承認。AI化しない

| 業務 | レベル | 使うSkill | 人間の役割 |
|---|---|---|---|
| 受信メールの仕分け・要対応抽出 | L3 | `mail-triage` | 結果一覧を見るだけ |
| メール返信文の作成 | L2 | `mail-reply` | ドラフト確認→自分で送信 |
| 議事録の整形・ToDo抽出 | L2 | `minutes` | 決定事項の正誤確認 |
| 週報・定型レポート | L2 | `weekly-report` | 数値と所感の確認 |
| リサーチ・要約 | L2 | `research-brief` | 結論の妥当性判断 |
| 提案書・プレゼン構成 | L2 | `proposal-draft` | 訴求ポイントの決定 |
| SNS投稿・デザイン指示書 | L2 | `sns-post` | トーン確認→自分で投稿 |
| スクリプト・ツール開発 | L2 | `dev-script` | 要件定義と受け入れ確認 |
| 資産の棚卸し・改善 | L2 | `asset-review` | 改善の採否判断 |
| 最終送信・公開・課金・削除 | L0 | なし | **常に人間が実行** |
| 顧客との関係構築・交渉 | L0 | なし | 人間専任 |

## 3. 優先順位(効果 × 頻度 × リスク)

| 優先 | 対象 | 理由 |
|---|---|---|
| 1 | メール処理(triage + reply) | 毎日発生・件数が多い・型化しやすい・失敗してもドラフト段階で止まるので低リスク |
| 2 | 議事録・週報 | 毎週発生・完全に型化できる・品質ブレが一番減らしやすい |
| 3 | リサーチ・要約 | 時間がかかる割に型が決まっている。ブリーフ形式に固定すると判断も速くなる |
| 4 | 提案書・SNS | 効果は大きいが「訴求の判断」が絡むため、テンプレ+QAで支える設計が先 |
| 5 | 開発SOP | 開発そのものよりも「要件→実装→テスト→記録」の型を固定して手戻りを防ぐ |

**判断基準(今後新しい自動化を思いついたときに使う):**
週1回以上発生 × 1回15分以上 × 失敗しても取り返せる → Skill化する。
どれか欠けるなら、まずテンプレ or チェックリストだけ作る。

## 4. ロードマップ

### Phase 1: 今日から(本コミットで完了)
- Skill 9本、テンプレート6本、QAチェックリスト4本、運用ルール、プロンプト集を整備
- 使い方: Claude Code でこのリポジトリを開き、「メール整理して」「議事録にして」等と依頼するだけでSkillが起動する

### Phase 2: 1〜2週間(運用して調整)
- 毎回の利用後、直した箇所をSkill・テンプレに反映(`asset-review` を週1で実行)
- メール返信の「自分の文体サンプル」を `templates/メール返信パターン集.md` に3〜5通貼り付ける(効果大)
- 提案書の過去の勝ちパターンを `templates/提案書テンプレート.md` に反映

### Phase 3: 1〜2ヶ月(半自動運転へ)
- 定着したSkillに定期実行(Routine/トリガー)を設定:毎朝のメールトリアージ、毎金曜の週報ドラフト
- Notion/Drive の保存先が確定したら、Skillに保存先パスを書き込み「作成→保存」まで一気通貫に
- 効果測定: 週の作業時間を before/after で記録(asset-review に項目あり)

## 5. この資産の全体像

```
claude-ai-tools/
├── docs/            ← 戦略・運用ルール(このファイル含む)
├── .claude/skills/  ← Claude Codeが自動で使う9つのSkill
├── templates/       ← 成果物の型(提案書・議事録・週報・メール等)
├── checklists/      ← 提出前QAチェックリスト
└── prompts/         ← Claude Code以外(claude.ai等)でも使えるプロンプト集
```

改善のルール: **成果物を手で直したら、その直しをテンプレかSkillに必ず還元する。** これが「業務資産として蓄積」の唯一のエンジンです。
